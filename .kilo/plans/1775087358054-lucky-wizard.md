# Code Review - Página HOME

## Resumo Executivo

A página HOME possui ~37 componentes organizados em 12 subdiretórios. A arquitetura geral é **sólida** — separação de concerns entre `features/catalog` (dados) e `components/layout` (UI) é clara. Porém há oportunidades significativas de melhoria em reutilização, consistência de padrões e redução de duplicação.

**Score geral: 7/10** — Bom fundamento, mas com dívidas técnicas identificáveis.

---

## 1. Responsabilidades (SRP)

### 1.1 `get-home-products.ts` — Lógica de transformação acoplada ao serviço
**Arquivo:** `src/features/catalog/services/get-home-products.ts`

**Problema:** O serviço mistura 3 responsabilidades:
1. Leitura do mock (`requestProductsMockFile`)
2. Transformação dos dados brutos em DTOs (`toHomeCandidate`, `toBadge`, `toDiscountPercent`)
3. Filtragem e ordenação para cada seção (flash sale, best sellers, new arrivals)

**Impacto:** Quando a API real chegar, toda a lógica de transformação precisará ser extraída ou movida para o backend. O `getHomeProducts()` tem 35 linhas de filtering/sorting que deveriam ser separáveis.

**Refatoração sugerida:** Extrair as funções de transformação para um módulo `transformers/` separado:

```typescript
// ANTES (tudo em get-home-products.ts)
export async function getHomeProducts(): Promise<HomeProductsPayload> {
  const mockFile = await requestProductsMockFile();
  const candidates = mockFile.products.map(toHomeCandidate).filter(Boolean);
  const flashSaleProducts = candidates.filter(...)...;
  const bestSellerProducts = candidates.filter(...)...;
  // ...
}

// DEPOIS
// src/features/catalog/transformers/home-products-transformer.ts
export function toHomeCandidates(products: MockCatalogProduct[]): HomeCandidate[] { ... }
export function selectFlashSaleProducts(candidates: HomeCandidate[]): HomeProductCard[] { ... }
export function selectBestSellerProducts(candidates: HomeCandidate[]): HomeProductCard[] { ... }
export function selectNewArrivalProducts(candidates: HomeCandidate[]): HomeNewArrivalProduct[] { ... }

// src/features/catalog/services/get-home-products.ts (fica limpo)
export async function getHomeProducts(): Promise<HomeProductsPayload> {
  const mockFile = await requestProductsMockFile();
  const candidates = toHomeCandidates(mockFile.products);
  return {
    flashSaleProducts: selectFlashSaleProducts(candidates),
    bestSellerProducts: selectBestSellerProducts(candidates),
    newArrivalProducts: selectNewArrivalProducts(candidates),
  };
}
```

**Ganho:** Testabilidade das transformações isoladamente; facilidade de migração para API real.

### 1.2 `NewArrivalsSection` — Carousel + ícones + lógica misturados
**Arquivo:** `src/components/layout/new-arrivals/new-arrivals-section.tsx`

**Problema:** O componente define 2 ícones SVG inline (`ChevronLeftIcon`, `ChevronRightIcon`), gerencia o estado do Embla carousel, e renderiza a seção. Três responsabilidades em um arquivo.

**Refatoração:** Mover os ícones para `src/components/ui/icons/` e extrair a lógica do carousel para um hook customizado:

```typescript
// src/hooks/use-carousel.ts
export function useCarousel(options?: Parameters<typeof useEmblaCarousel>[0]) {
  const [emblaRef, emblaApi] = useEmblaCarousel({ align: "start", containScroll: "trimSnaps", ...options });
  const scrollPrev = useCallback(() => emblaApi?.scrollPrev(), [emblaApi]);
  const scrollNext = useCallback(() => emblaApi?.scrollNext(), [emblaApi]);
  useEffect(() => { return () => { emblaApi?.destroy(); }; }, [emblaApi]);
  return { emblaRef, scrollPrev, scrollNext, emblaApi };
}
```

### 1.3 `MiniProductCard` — Formatação de moeda duplicada
**Arquivo:** `src/components/layout/new-arrivals/mini-product-card.tsx:73-74`

**Problema:** A formatação de preço (`originalPrice.toFixed(2).replace(".", ",")`) é duplicada em `MiniProductCard` e `ProductPrice`. É lógica de apresentação que deveria ser uma utility function.

**Refatoração:**
```typescript
// src/lib/format-currency.ts
export function formatBRL(value: number): string {
  return `R$ ${value.toFixed(2).replace(".", ",")}`;
}
```

**Ganho:** Um único lugar para alterar formatação de moeda se precisar de i18n no futuro.

### 1.4 `AddToCartButton` vs `MiniProductCard` — Comportamento de carrinho inconsistente
**Arquivo:** `src/components/layout/flash-sale/add-to-cart-button.tsx` vs `src/components/layout/new-arrivals/mini-product-card.tsx:76-79`

**Problema:** `AddToCartButton` é um botão puramente visual (sem `onClick`), enquanto `MiniProductCard` tem um `handleAddToCart` com `console.log` hardcoded. Nenhum dos dois integra com um store de carrinho real.

**Refatoração:** Criar um único componente `AddToCartButton` que aceite `onAdd` como prop, e conectar com zustand (já no projeto) via um custom hook:

```typescript
// src/features/cart/hooks/use-add-to-cart.ts
export function useAddToCart(productId: string) {
  const addItem = useCartStore((s) => s.addItem);
  return useCallback(() => addItem(productId), [addItem, productId]);
}
```

## 3. Boas Práticas

### 3.1 Performance — Re-renderizações desnecessárias

**Problema:** `CountdownTimer` não usa `memo` e é renderizado dentro de `FlashSaleSection` que recebe um array de products. Embora o timer seja isolado via `"use client"`, ele recria a função `parseTime` a cada render.

**Verificação:** `parseTime` é pura e está fora do componente — isso é correto.

**Observação positiva:** `CountdownUnit` usa `preserveValue` do CountUp corretamente para evitar flicker.

### 3.2 Acessibilidade

**Problemas identificados:**

1. **`FeatureItem` (`feature-item.tsx:29`):** `alt=""` com `aria-hidden` no ícone — **correto**, mas o componente não tem `aria-label` no container. Screen readers não saberão o que "Frete Grátis" significa sem contexto.

2. **`CategoryNavItem` (`category-nav-item.tsx:24-37`):** O `<Link>` não tem `aria-label` descritivo. O conteúdo usa `absolute` positioning que pode confundir a ordem de leitura de screen readers.

3. **`PromoMarquee` (`promo-marquee.tsx:13`):** O marquee duplica itens e usa `key={i}` com index. O `aria-live` não está configurado para conteúdo que se move automaticamente. WCAG 2.2.2 requer mecanismo de pausa para conteúdo auto-animado.

4. **`FlashSaleBadge` (`flash-sale-badge.tsx:11`):** SVG com `aria-hidden` — **correto**.

5. **`StarRating` (`star-rating.tsx:40`):** Não tem `aria-label` como "4.5 de 5 estrelas". Screen readers verão apenas 5 SVGs e "(120)".

**Refatoração para StarRating:**
```typescript
export function StarRating({ rating, count }: StarRatingProps) {
  const filledCount = Math.round(rating);
  return (
    <div className="flex items-center gap-1" aria-label={`${rating} de 5 estrelas, ${count} avaliações`}>
      <div className="flex gap-0.5" aria-hidden>
        {Array.from({ length: 5 }, (_, i) => (
          <StarIcon key={i} filled={i < filledCount} />
        ))}
      </div>
      <span className="text-xs leading-4 text-text-muted">({count})</span>
    </div>
  );
}
```

### 3.3 Naming Conventions

**Positivo:** Nomes de componentes são consistentes (PascalCase), arquivos em kebab-case, interfaces com sufixo `Props`.

**Problema:** `useHomeProducts` — a convenção `use` sugere um hook de React (com acesso a lifecycle/state), mas este é apenas um wrapper de `React.cache()`. Seria mais preciso chamar de `getHomeProducts` ou `cachedHomeProducts`.

### 3.4 Hardcoded Values / Magic Numbers

**Problemas:**
- `countdown-timer.tsx`: `FLASH_SALE_INITIAL_SECONDS = 12 * 3600 + 19 * 60 + 34` — hardcoded em constants mas sem vir de API
- `best-sellers-section.tsx:62`: `grid grid-cols-4 gap-5` — número de colunas fixo sem responsividade
- `promo-card.tsx:172`: `left-[227px] top-[181px]` — posicionamento mágico do badge de desconto
- `category-nav-item.tsx:28-34`: `top-[14px] left-[22px]`, `top-[46px]`, `top-[77px]` — posicionamento absoluto mágico

**Refatoração para CategoryNavItem:** Usar flexbox em vez de absolute positioning:
```typescript
// ANTES
<Link className="relative w-46.5 h-29.75 ...">
<span className="absolute ... top-3.5 left-5.5">{emoji}</span>
<span className="absolute ... top-11.5 left-5.5">{title}</span>
<span className="absolute ... top-19.25 left-5.5">{subtitle}</span>
</Link>

// DEPOIS
<Link className="w-46.5 h-29.75 flex flex-col justify-center px-5.5 ...">
  <span className="text-2xl leading-8">{emoji}</span>
  <span className="font-black text-sm leading-5 ...">{title}</span>
  <span className="text-xs leading-4 ...">{subtitle}</span>
</Link>
```

### 3.5 Tipagem

**Positivo:** Interfaces `Props` bem definidas em todos os componentes. Tipos exportados de `features/catalog/types/` são usados consistentemente.

**Problema:** `PromoCard` aceita `title: string` com `\n` para múltiplas linhas. Isso mistura dados com apresentação. Melhor seria aceitar `title: string[]`.

### 3.6 Efeitos Colaterais

**Problema:** `NewArrivalsSection` tem cleanup do Embla API (`useEffect` com `emblaApi.destroy()`), mas o próprio Embla hook já faz cleanup interno. O efeito é redundante.

```typescript
// LINHAS 90-96 de new-arrivals-section.tsx — REMOVER
useEffect(() => {
  return () => {
    if (emblaApi) {
      emblaApi.destroy(); // Embla já faz isso internamente
    }
  };
}, [emblaApi]);
```
